# Feature Statistics User Guide

This folder contains tools to evaluate feature quality from the HDF5 file generated by the Jalmar preprocessing/feature pipeline.

- Script: `features_stats.py`
- Goal: rank features and visualize how well they separate sleep stages for mcRBM feature set selection.

## What This Analysis Produces

The script computes:

1. Global descriptive stats per feature (mean, std, IQR, skew, kurtosis, outlier %)
2. Per-stage stats per feature (Awake, N1, N2, N3, REM)
3. Discriminability metrics:
   - Mutual information
   - Fisher score
   - Eta-squared
   - ANOVA and Kruskal-Wallis statistics
4. Composite feature ranking score for feature selection
5. Diagnostic plots for feature behavior and redundancy

## Input Requirements

Your HDF5 file should follow the structure generated by `Jalmar/hdf5/hdf5_creation.py`:

- One group per subject
- Dataset `features` with shape `(n_epochs, n_features)`
- Dataset `scores` with shape `(n_epochs,)`
- Optional attribute `description_features` with comma-separated feature names

## Environment Setup

From the workspace root:

```powershell
pip install -r Jalmar/requirements.txt
```

## How To Run

Basic usage:

```powershell
python Jalmar/stats/features/features_stats.py --hdf5 "C:/path/to/sleep_features.h5" --output_dir "Jalmar/stats/features/output"
```

Include movement/artifact stage (stage 5) in analysis:

```powershell
python Jalmar/stats/features/features_stats.py --hdf5 "C:/path/to/sleep_features.h5" --output_dir "Jalmar/stats/features/output" --include_artifacts
```

## How To Interpret Results

Use this workflow for mcRBM feature set selection:

1. Start with `feature_ranking.csv`
   - Higher `selection_score` means stronger stage-separation evidence.
2. Open `feature_correlation_heatmap.png`
   - Remove highly redundant features (very high absolute correlation).
3. Inspect per-feature plots in `per_feature/`
   - Prefer features with clear stage-wise distribution shifts and lower overlap.
4. Check `feature_stage_stats.csv`
   - Verify that separation is not driven by only one rare stage.
5. Build a candidate subset
   - Keep top-ranked, non-redundant features.

## Hypnogram Stage Mapping

Hypnogram plots in this folder are generated from feature-derived transitions (not only from original labels):

- Wake: `Index_W`
- REM: `Index_R`
- NREM gate: `Index_N`
- NREM subtype split:
   - N1: `Index_1`
   - N2: `Index_2`
   - N3: `Index_3`

Rule used per epoch:

1. Choose broad state by max(`Index_W`, `Index_N`, `Index_R`): Wake / NREM / REM
2. If NREM wins, choose subtype by max(`Index_1`, `Index_2`, `Index_3`) -> N1/N2/N3

If required index columns are missing, the script falls back to stored `scores` from HDF5.

## Practical Selection Tips

- Prefer features with high mutual information and high eta-squared.
- Favor stable distributions (reasonable outlier % and not extreme skew/kurtosis).
- Avoid selecting many features that encode the same signal pattern.
- Re-run after changing preprocessing settings to compare ranking stability.

## Troubleshooting

- No data found:
  - Confirm the HDF5 has `features` and `scores` datasets per subject group.
- Unexpected feature names:
  - If `description_features` is missing or malformed, fallback names `Feature_1`, `Feature_2`, ... are used.
- Plot generation is slow:
  - This is expected for many epochs and many features; per-feature plot generation dominates runtime.

## Recommended Next Step

After selecting a subset, run a small downstream benchmark (e.g., stage prediction baseline or mcRBM latent-state quality check) and compare against the full feature set.
